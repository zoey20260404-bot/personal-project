# feat002 需求文档：多轮追问（多 Agent 智能对话中枢）

> 版本：v0.1（草案） 日期：2026-09-06
> 关联：feat001（条件解析/岗位查询已落地） · [迭代 TODO](../feat001/iteration-todo.md)

## 1. 背景与目标

feat001 已完成条件解析工作流（确定性流程）。本需求将「多轮追问」升级为**多 Agent 智能对话中枢**：用户以自然语言对话，系统理解意图并分发给对应专业 Agent 处理。

目标：从"AI 工作流"演进为"工作流骨架 + 意图路由决策点"的混合形态（企业主流实践，见 README 架构理念）。

## 2. 用户场景

1. **选岗咨询**："我这个条件，广东有哪些稳一点的岗？"、"A 岗和 B 岗哪个好？"
2. **档案补充**："我入党了"、"我工作两年了" → Agent 识别为档案修正意图，更新用户档案
3. **笔试备考**："给我出道资料分析题"、"帮我批改这篇申论"
4. **面试模拟**："模拟一场结构化面试"
5. **无领导小组**：多人角色扮演的讨论模拟（后续迭代）

## 3. Agent 角色划分

| Agent | 职责 | 工具白名单 |
| --- | --- | --- |
| Router | 意图识别与分发，低置信度时反问澄清 | 无 |
| 选岗参谋（advisor） | 智能匹配 → 竞争分析 → 冲稳保推荐；档案查询/补充；收藏操作 | query_positions、get_profile、update_profile、add_favorite |
| 笔试中枢（exam_coach） | 行测诊断出题、申论批改 | query_questions、submit_answer（题库工具，依赖数据源） |
| 面试考官（interviewer） | 结构化面试模拟、追问点评 | 无（纯对话驱动） |
| 无领导小组（group_discussion） | 多角色扮演讨论模拟（每个考生一个 persona Agent，回合制编排） | 无 |

## 4. 功能需求

### 4.1 意图路由

- chat 入口统一接收自然语言，Router Agent 判断意图并分发到对应 Agent
- 意图置信度低时反问用户澄清（"你是想选岗，还是练面试？"）
- 多轮对话中支持意图切换（会话状态保留）

### 4.2 档案补充（chat 内条件修正）

- 用户在对话中补充/修改条件（"我入党了"）→ 识别为档案修正意图
- 复用 feat001 的解析 + 档案合并规则：明确提及的字段覆盖，未提及的保留旧值
- 修改前 Agent 口头确认（human-in-the-loop）："我将把政治面貌更新为中共党员，确认吗？"

### 4.3 记忆

- 会话消息写入长期记忆（session 作用域）
- 回答时召回：历史对话（session）+ 用户画像（user）+ Agent 经验（agent）
- 跨会话记忆：用户画像类信息跨会话可见

### 4.4 响应形态

- 流式输出（SSE），首包 < 500ms
- beginner/advanced 双模式表达（复用 Prompt 变体机制）
- 回答必须基于工具返回的数据，标注来源，禁止编造岗位/分数线

## 5. 非功能需求

- 工具权限：Agent 只能调用白名单内工具（配置级隔离）
- 数据安全：工具执行的用户身份来自 JWT context，不接受模型传入的 user_id
- 可靠性：ReAct 循环 max_steps 封顶、单步超时、节点崩溃隔离（现有 runtime 已具备）
- 可观测：TraceID 贯穿 chat → router → agent → 工具调用全链路

## 7. 验收标准

- chat 输入选岗问题 → 正确路由到选岗参谋并返回基于真实数据的回答
- chat 输入"我入党了" → 档案更新且回复确认变更内容
- 意图模糊时 → 反问澄清而不是硬猜
- Agent 调用白名单外工具 → 被拒绝
