# 项目开发规则

1. **代码注释**：编程过程中需要添加注释。
2. **项目规范**：当前项目需要对标企业级开发规范化，项目目录需要划分明确。
3. **文档要求**：每个需求需要有对应的需求文档和技术文档，技术文档在写代码过程中同步更新。
4. **文档位置**：每个需求的文档位于 `docs` 目录下的子目录中，例如 `xxx-prd-dev数字` 格式的目录。
5. **用户偏好1**：在变更代码之前，都需要把方案告知用户，等用户确认之后才可以变更代码。
6. **用户偏好2**：在迭代需求过程中，测试过程中出现的问题或者其他遇到的有代表性意义的问题及解决，都要写在对应每个需求的文档位目录中，文件名可以为problem-solve。
7. **用户偏好3**：代码尽可能优雅和可拓展可维护。
8. **用户偏好4**：当用户要验证交互时，除了给出访问的html地址，也需要自行启动服务。
9. **用户偏好5**：config模板，改动要同步更新到config的example中，除了一些私密信息如密钥，apiKey
